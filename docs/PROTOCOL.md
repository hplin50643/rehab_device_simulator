## 封包格式

```text
位置       0     1      2        3 .. 2+N      3+N       4+N
內容      7A   command  N        payload     checksum     7F
大小       1     1      1          N             1         1 byte
```

總長度為 N + 5，N 為 0–255。線上傳送真正 bytes，畫面 HEX 僅用來閱讀，不加換行、不加文字編碼、不使用 JSON 包覆。

```python
checksum = 255 - ((command + len(payload) + sum(payload)) % 256)
```

從 command 到 checksum 加總取低 8 bits 應為 `FF`。資料內可以出現 `7A` 或 `7F`，不能單純用結尾分割 TCP stream。TCP 一次 recv 可能包含半包或多包。

## 命令表

所有數字除另註外皆為 HEX；正常／成功 `C8`，異常／拒絕 `C9`。

| 命令 | 方向 | payload | 行為 |
| --- | --- | --- | --- |
| `20` | 主機 → 機台 | `00`／`01`／`02` | 查詢讀卡器／機台／心率裝置 |
| `20` | 機台 → 主機 | `selector C8` 或 `selector C9` | 狀態回覆；機台只有硬體狀態 Start 為正常，與 tracking 分開 |
| `20` | 機台 → 主機 | `02 C9` | 異常停止時若心率裝置失聯，另外主動通知 |
| `21` | 機台 → 主機 | UID bytes | 1–255 bytes，HEX 前導零保留；不假設固定 4 bytes |
| `21` | 主機 → 機台 | `C8`／`C9` | 可辨識的卡號 ACK；NCKUHSport 補充證據 |
| `22` | 主機 → 機台 | `00`／`01`／`02` | 停止／開始／暫停 |
| `22` | 機台 → 主機 | `action C8` | 停止約 3.5 秒、開始約 0.5 秒後回覆；暫停立即回覆 |
| `23` | 機台 → 主機 | `00 value`／`01 value`／`02 value` | RPM／回報 Level／BPM；value 為單 byte 0–255，不等待 ACK |
| `24` | 機台 → 主機 | `00` | 異常停止通知；沒有推定對端必須 ACK |
| `25` | 主機 → 機台 | 1 或 2 bytes | big-endian 目標 Level，0–65535 |
| `25` | 機台 → 主機 | `C8` | 確認收到阻力設定，不保證已套用到模擬硬體 |

特別注意方向：收到 `25 C8` 是 Level **200**，不是本機等待的 ACK；送出 `25 C8` 才是回覆收到阻力指令。`21 C8` 作為收到的回覆可辨識為 ACK，但作為送出的單 byte UID 仍是合法卡號。

## 保留的原版行為

- 冷啟動：未追蹤、機台 End、讀卡器／心率裝置未就緒，全部數值為 0。模擬器不執行實體硬體初始化；狀態由使用者控制。
- START／STOP 的追蹤切換與 ACK 在延遲結束時執行。重疊控制以 FIFO 計時，等待期間接收不阻塞。PAUSE 只 ACK，不改 tracking，也不把硬體自動設為 Pause。
- 追蹤中且啟用自動回報時，只有相較基準改變的數值會送出 `23`；第一次開始可送出先前調整的非零值。單次送出可明確強制傳送，不需要 tracking。
- 目標 Level 與回報 Level 分離。自動跟隨開啟時，非零新目標套用到回報值；關閉時只更新目標。手動改值不會修改最近目標。
- Level 0 確認收到但不套用。大於 255 保留原始目標／模擬值並警告，禁止遙測與手動單次送出該超界值；使用者可另改回 0–255。
- 自動跟隨開關影響後續主機指令，切換本身不重新套用上一筆目標。
- 異常停止清除尚待執行的啟停、停止 tracking；自動跟隨開啟時硬體轉 End。心率失聯則另排入 `20 02 C9`。
- 非 `23` 主動通知在單一待回覆槽等待，每次 0.5 秒、最多共 3 次傳送（首次 + 2 次重送）。任何通過校驗的 RX 可結束該 legacy 等待，控制命令仍會正常分派。
- 真正 `21 C8/C9` 分別標成已確認／被拒絕。其他有效資料只標成「收到資料，非明確 ACK」。沒有 RX 到達時是送達狀態未確認，不代表協定錯誤或確定未送達。

## 主動修復的可靠性問題

| 原版風險 | 本工具處理 |
| --- | --- |
| 假設一次 recv 就是一個完整封包 | 長度感知的 stream decoder，支援拆包、黏包及內含分隔 bytes |
| 損毀資料仍執行、校驗不完整 | 嚴格檢查長度、邊界及 checksum；錯誤只記錄不執行 |
| 偽造長度卡住後續資料 | 不完整封包 2 秒到期重新同步；緩衝上限 16 KB |
| 等 ACK 的 recv 吞掉控制命令 | 唯一接收迴圈，先完成等待判定，仍分派每個有效命令 |
| EOF／失敗後殘留假連線 | 明確連線狀態、generation 防舊候選掛接、使用者手動斷線停止重試 |
| 回覆互相 echo 形成迴圈 | 已知回覆不再回覆；未知命令每連線僅 echo 相同封包一次，最多 128 種 |
| 跨連線重送舊刷卡或排程 | 斷線取消待送／待確認／啟停計時；不重播舊事件 |
| 把排隊或任何 RX 說成成功 | 分別記錄排隊、實際 TCP 寫入、可辨識 ACK、其他資料及未確認 |
| 大數值截斷成單 byte | 嚴格拒絕非法手動值，收到超界 Level 時顯示並抑制非法回報 |

控制回覆不進入主動重送等待，也不要求對端 ACK。已知命令但資料格式不支援時，僅記錄、不變更機台狀態；未知命令的有限 echo 保留原版互通意圖但避免無限循環。

## APK 證據與限制

NCKUHSport 的 `RaspberryPiManager.cs` 194–210 行支持 `21` 的單 byte `C8/C9`，267–274 行支持送一 byte Level。`LoginController.cs` 179–190 行顯示卡號 ACK 在課程查詢之前，不可解讀成登入／課程成功。在已查閱路徑中，未找到 `24` 或主動 `20` 的必要 ACK；`23` 的 ACK helper 存在但未見呼叫。

以上是靜態程式閱讀，不是實際 APK 互通測試。RunRunAnimals 為不同的 IL2CPP 產物，目前僅有型別／方法線索，不足以確認相同行為。也未驗證真實硬體、平板課程流程、BLE 或 UART。

原版 torque、瓦數、距離及熱量資料來自串列埠分支；本版 TCP 未定義對應封包。UI 使用 Level，不顯示 Nm、不推算功率或熱量。
